# Projeto

Esta pasta passa a ser o ponto central de leitura do projeto.

Objetivo:

- concentrar os documentos estruturantes em um unico lugar;
- reduzir dispersao entre decisoes, contrato operacional e proximas etapas;
- deixar um caminho de leitura claro para descoberta local e operacao com
  Supabase e Cloud Run.

## Ordem recomendada de leitura

1. [`01-visao-geral.md`](01-visao-geral.md)
2. [`02-arquitetura-alvo.md`](02-arquitetura-alvo.md)
3. [`06-proximas-etapas.md`](06-proximas-etapas.md)
4. [`../decisao-supabase-cloud-run.md`](../decisao-supabase-cloud-run.md)

Documentos `03`, `04` e `05` registram a arquitetura anterior baseada em n8n e
Google Planilhas. O documento `07` ainda preserva referencias uteis sobre os
catalogos, mas suas secoes de n8n e Google Drive foram substituidas pela
decisao vigente.

## Fonte canonica e legado

Nesta fase, `docs/projeto/` vira o hub central de leitura.

Os arquivos antigos em `docs/` continuam existindo como historico e apoio de
transicao, mas os documentos desta pasta passam a ser a leitura principal para
o bloco atual de descoberta local, Supabase, Cloud Run e operacao autonoma.

A decisao canonica vigente esta em
[`../decisao-supabase-cloud-run.md`](../decisao-supabase-cloud-run.md).
